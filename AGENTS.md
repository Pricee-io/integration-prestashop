# AGENTS.md

Guidance for AI coding agents working in this repository.

## Project

Pricee.io PrestaShop plugin (`pricee/`): syncs PrestaShop products to the Pricee.io platform. PHP 7.4+, PrestaShop 1.7.8+.

- `pricee/pricee.php` — main module class (configuration, category listing)
- `pricee/src/Controller/Admin/SyncController.php` — AJAX sync endpoint
- `pricee/src/Service/SyncService.php` — sync logic and Pricee.io API calls
- `pricee/views/templates/admin/` — Smarty admin templates (French labels)

## Development

All tooling runs through the Docker dev environment (see `Makefile`):

- `make dev` — shell into the dev container
- `make lint` — php-cs-fixer (fix), `make lint_ci` — dry-run check
- `make analyze` — phpstan
- `make rector` — rector
- `make package` — regenerate `pricee.zip` for release

Run lint and analysis before committing.

## Versioning

The plugin follows [Semantic Versioning](https://semver.org/). The version is defined in three places and all must be updated together:

1. `$this->version` in `pricee/pricee.php`
2. A new `## [x.y.z] - YYYY-MM-DD` entry at the top of `CHANGELOG.md`
3. `<version>` in `pricee/config.xml` (stays in sync with the module version; regenerated by PrestaShop on install)

Bump rules:

- **Patch** (`1.1.0` → `1.1.1`): bug fixes, no behavior change
- **Minor** (`1.1.0` → `1.2.0`): new features or backward-compatible behavior changes
- **Major** (`1.1.0` → `2.0.0`): breaking changes (PrestaShop compatibility drops, config/DB schema changes)

Make the version bump its own commit, titled `Bump version to x.y.z`, separate from feature commits.

Changelog rules (this is a PrestaShop module, so the changelog is read by merchants, not developers):

- Only user-facing changes: what the module user sees or experiences in the back office or front office. Skip CI, tooling, Dependabot, static analysis and internal refactors.
- One short line per change, no implementation details (no function names, no file paths, no "fix X by doing Y" narration).

## Webhook contract

The price-update webhook is received by `pricee/controllers/front/webhook.php` (module front controller `webhook`). The payload is a JSON array of entries signed with HMAC-SHA256 over the **raw request body** using the webhook secret (`X-Signature` header). Each entry carries `url`, `extId` (optional: the shop's internal product ID, null for products synced before external IDs existed), `bestPriceAmount`, `bestPriceCurrency`, `timestamp` and `nonce`; entries with a missing/stale timestamp or an already-used nonce are rejected (replay protection). Products are matched by `extId` when present, with a fallback to the product URL.

Any change to this format is a cross-repo contract: the sender lives in `../app/src/Service/WebhookService.php` and the WooCommerce/Sylius integrations validate the same signature, keep changes backward compatible or coordinate all of them.
